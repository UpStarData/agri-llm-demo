**区域 8 色**：`#cfe9bd` `#e2efc6` `#b6dfa4` `#eae7c4` `#c9e6cd` `#d7e4b2` `#bcdcc9` `#e8f0d8`

**"不同区域不同色"是算出来的，不是固定映射**：
1. 取每个区域边界顶点（保留 3 位小数）；
2. **两个区域共享 ≥2 个顶点**才算接壤（只碰一个点不算，避免四角相接误判）；
3. 区域按"邻居数从多到少"排序，依次取"邻居里还没用过的最小颜色下标"；
4. 最多用到 8 色，超出回绕。

### 三个视角的相机参数

| 视角 | 底图 | center | zoom | 可缩放 | 层级切换 |
|---|---|---:|---:|---|---|
| L1 全球 | `worldChina` | `[107.98, 26.65]` | `1.36` | 1.1 – 2.6 | 放大到 ≥2.15 进中国 |
| L2 中国 | `china` | `[108.05, 36.15]` | `1.59` | 0.85 – 4 | 放大到 ≥2.6 进湖南；缩小到 ≤0.95 回全球 |
| L3 湖南 | `china` | `[111.73, 27.54]` | `9.08` | 3.4 – 16 | 缩小到 ≤3.5 回中国 |

两个必须知道的技术细节：
- **L1 画三份世界副本**（经度 ±360°）：`[-1,0,1].map(c => worldLongitude(lng) + c*360)`。统计点位前要按经度归一到 `[-180,180)` 再去重，否则是 3 倍。
- **叠加图层按视角裁剪**：全球全量；中国 `lng 73–136 / lat 17.5–54.5`；湖南 `lng 108–115 / lat 24–31`；全球视角机场最多取 180 个（地理均衡采样）。

## 二、事实点（点本身）

| 属性 | 取值 |
|---|---|
| 形状 / 尺寸 | 圆点，直径 **6px**（屏幕像素，不随 zoom 变） |
| 填充色 | 该事实的**一级分类色**（见第三章） |
| 外圈 | `rgba(255,255,255,.92)`，线宽 **0.9** |
| 透明度 | `ageAlpha × 动画系数`（见下表） |
| 同坐标合并 | 多条记录合成一个点；点击弹"此位置共 N 条事实" |

**透明度 `ageAlpha`**：时间窗 = 全部 或 档案类 → `0.9`；距今 ≤30 天 → `1.0`；30–60 天 → `0.9`；60 天以后线性降到 `0`（窗口边界处正好消失）。

## 四、地理影响圆（影响圆 / 光晕）—— 设计规则全表

### 4.1 它想表达什么

影响圆 = **一条事实的影响范围**：以事实所在经纬度为圆心，按该事实的"影响半径（公里）"在地图上画一个**径向渐变光晕**，用来在不加粗点位的前提下表达"这件事波及多大一片"。视觉上是暖/冷调很浅的雾状圆，不是实心圆、不是描边圈。

### 4.2 半径从哪来（关键：目前全部是推算值）

`pkg-adapter.js` 的规则：

| 情况 | 半径取值 | `radiusEstimated` |
|---|---|---|
| 数据包给了 `geo.impactRadiusKm > 0` | 直接用真实公里数 | `false`（真实） |
| 没给（当前几乎全部） | `radiusOf(severity) = 80 + round(severity × 3.2)` 公里，缺 severity 时兜底 `140` km | `true`（推算） |

**实测（重要）**：当前数据里 **141 条"高影响"事实的 `impactRadiusKm` 全部缺失**，即 `radiusEstimated = true` 的占 141/141，**真实半径 0 条**。也就是说现在看到的影响圆，语义上是"按严重度折算的影响范围"，不是来源给出的真实影响半径。

### 4.3 哪些点会画影响圆（2D 规则）

| 条件 | 取值 | 说明 |
|---|---|---|
| 图层开关 | `sk.influence = true`（默认开） | 关掉则整层不画（`halo` 与 `ripple` 一起清空） |
| 影响等级 | **仅 `impact === 'high'`**（severity ≥ 70） | mid（40–69）、low（<40）不画 |
| 半径 | `radius > 0` 且为有限数 | 因适配层总会兜底填半径，**2D 实际不校验是否为推算值** |
| 数量上限 | **最多 24 个** | 超出不再画（按遍历顺序先到先得） |
| 屏幕间距 | **相邻光晕圆心 ≥ 40px** | 按像素算（不是经纬度），太近的后面的不画，避免叠成一大块 |
| 必须落在可视区 | 圆心像素在画布内 | 否则不画 |

### 4.4 半径怎么变成屏幕像素（含 88px 上限）

```
kmPerPixel = (L1 ? 40075 : 6900) / (画布宽 × zoom)      // 全球用地球周长，中国/湖南用 6900km 近似
直径px     = 2 × radiusKm / kmPerPixel
实际绘制尺寸 = min(88, max(16, 直径px × 1.2))
```

1440px 宽下的换算（括号内为最终绘制尺寸）：

| 视角 | km/px | 90km | 120km | 160km | 220km | 300km | 420km |
|---|---:|---|---|---|---|---|---|
| L1 全球 | 20.46 | 9px (16) | 12px (16) | 16px (19) | 22px (26) | 29px (35) | 41px (49) |
| L2 中国 | 3.01 | 60px (72) | 80px (88) | 106px (**88**) | 146px (**88**) | 199px (**88**) | 279px (**88**) |
| L3 湖南 | 0.53 | 341px (**88**) | 455px (**88**) | 606px (**88**) | 834px (**88**) | 1137px (**88**) | 1592px (**88**) |

**这张表解释了实际观感**：全球视角下影响圆还能分出大小（19–49px），**到了中国/湖南，几乎所有都顶到 88px 上限**，于是看起来是一圈**尺寸恒定的雾状光晕**，而不是"半径等比放大"的圆。这是上限设计的结果，不是数据错了。

### 4.5 渐变与透明度

```
a0 = ageAlpha(f, 时间窗)            // 与点同一套时间衰减：0.9 / 1.0 / 线性降到 0
colorStops:
  0%   → 分类色，透明度 0.10 × a0    // 圆心最浓
  55%  → 分类色，透明度 0.04 × a0
  100% → 分类色，透明度 0
```
即：**圆心也只有 10% 不透明度**，非常淡；颜色跟事实的一级分类色一致（不是统一色），所以不同分类的雾会呈现各自的色调。

### 4.6 涟漪（高影响点的"呼吸"）

与影响圆同一批点（每个画了影响圆的点也会进涟漪队列，最多 8 个）：

| 参数 | 值 |
|---|---|
| 系列类型 | `effectScatter` |
| 数量上限 | **8** |
| 扩散周期 | `period: 7`（秒） |
| 扩散倍数 | `scale: 4.2` |
| 描边模式 | `brushType: 'stroke'` |
| 同时扩散数 | `number: 2` |
| 整体透明度 | `itemStyle.opacity: .55` |
| 触发方式 | `showEffectOn: 'render'`（进入即开始，不随鼠标） |

### 4.7 3D 地球上的影响圆（与 2D **不一致**）

```
halo       = (sk.influence && !f.radiusEstimated && radius>0) ? radius / 5200 : 0
haloAlpha  = { high: .18, mid: .13, low: .09 }[impact]
```
- 3D 要求 **半径必须是真的**（`!radiusEstimated`）→ 因为当前 141 条高影响全是推算值，**3D 地球上目前一个影响圆都没有**；
- 3D 的半径不套 88px 上限，而是按 `radius/5200` 换算成地球半径比例；透明度用固定的 `.18/.13/.09`，不乘 `ageAlpha`。

### 4.8 实测（1440×900，线上 V2.9 同版制品）

| 视角 | 画出的影响圆 | 实际尺寸范围 | 涟漪 |
|---|---:|---|---:|
| L1 全球 | **13** 个 | 27 – 31px | 8 |
| L2 中国 | **11** 个 | 88px（全部顶上限） | 8 |
| L3 湖南 | **20** 个 | 88px（全部顶上限） | 8 |

（数量少于 24 是因为受"仅高影响 + 40px 间距 + 可视区"三重过滤。）

### 4.9 前端复刻时必须知道的 3 件事

1. **语义**：现在的影响圆是**按严重度推算的雾**（`80 + severity×3.2` km），不是来源给的真实影响半径；文案里不要写成"实测影响范围"。
2. **2D / 3D 不一致**：2D 画推算半径、3D 不画。若要保持一致，二选一——要么 2D 也不画推算值（3D 现状），要么 3D 也放行推算值。要与线上完全一致，就照抄上面的两个条件。
3. **88px 上限**导致省域视角尺寸饱和。若想让省域也能看出差异，需要提高上限或改成"按 zoom 自适应"，这属于产品取舍，目前**没有**这么做。

## 五、新事实"亮起来"的效果（DOM + CSS，不是 SVG 也不是 canvas）

### 5.1 星星本体

```html
<div class="star-flash bright" style="left:908.7px; top:167.9px"><i></i></div>
```
```css
.star-flash{position:absolute;pointer-events:none;z-index:20;transform-origin:50% 50%;
  will-change:transform,opacity;animation:starFlash .9s cubic-bezier(.22,1,.36,1) forwards}
.star-flash i{display:block;width:14px;height:14px;margin:-7px 0 0 -7px;border-radius:50%;
  background:radial-gradient(circle,rgba(255,255,255,.98),rgba(255,236,150,.85) 38%,
             rgba(255,214,102,.25) 62%,rgba(255,214,102,0) 78%);
  box-shadow:0 0 10px rgba(255,220,120,.75)}
.star-flash.dim i{width:9px;height:9px;margin:-4.5px 0 0 -4.5px;opacity:.75;box-shadow:0 0 6px rgba(255,220,120,.5)}
.star-flash.bright i{transform:scale(1.5)}
@keyframes starFlash{
  0%{opacity:0;transform:scale(.3)} 20%{opacity:1;transform:scale(1.2)}
  50%{opacity:.7;transform:scale(1)} 100%{opacity:0;transform:scale(.5)}
}
```
要点：0.9 秒、缓动先冲后收、20% 处最亮（1.2 倍）、50% 回落、结束缩到 0.5 倍淡出；**暖金色**（不是分类色）；两档 `bright/dim`；同屏最多 6 颗；元素 1s 后自动移除；位置是屏幕像素，落在可视区外不画。矢量等价版见附件 `star-flash.svg`。

### 5.3 点的出现与消失

| 动画 | 参数 |
|---|---|
| 首屏铺点 | 分批揭示，约 6.5 秒铺完（页面内渐进，非网络流式） |
| 时间筛选铺点 | 今天 1.5s / 7 天 1.8s / 30 天 2.2s / 半年 2.7s / 一年 2.9s / 全部 3.2s；缓动 `1-(1-p)^2.2` |
| 动画中退场 | 随机取 `n/20`；每个点在动画 45%–82% 处开始淡出，时长占 18%，钳制到"动画结束前收干净" |
| 动画结束 | **冻结**，不再新增/消失 |
| 首屏之后 | 每 10s / 20s / 15s 循环退场 1 个坐标点（跨视角一致） |

## 六、复刻要点与坑

1. **不要开 ECharts `large` 模式**：会忽略逐点样式，所有点同色（V2.8.5 踩过）。
2. 世界副本 ×3：统计前按经度归一再 dedupe。
3. 同坐标合并：一个点可能是多条记录。
4. `--ocean` 只管"海"；陆地/边界/区域色在 `MAP_PALETTE`。
5. 无坐标事实（11 条直播源 `lng=null`）不参与点位/退场计算，取坐标键必须先判空（曾导致整页初始化失败）。
6. `freshFlash` 这个 ECharts 系列是历史遗留、没有数据源，亮星效果完全由 5.1 的 DOM+CSS 完成。
7. 影响圆的 24 个上限、40px 间距、88px 尺寸上限三者共同决定了"看起来有多少、有多大"，改动任何一个都会明显改变观感。
