# 版本发布地址约定（单仓库 · 按版本分目录）

> 产品要求（2026-09-22 修订）：**只有 `UpStarData/agri-llm-demo` 一个仓库**，每个版本在仓库内**分目录**；每个版本一个固定地址，旧版本也要能打开看。**不再为每个版本新建仓库**。

**版本号规则**：`V0.0` = 原版基线（迭代起点），以后每次发版在最新版本上加一个号（V0.8 / V0.9 / V1.0 …），旧版本目录与地址永久保留。仓库根地址 `https://upstardata.github.io/agri-llm-demo/` 显示的就是 V0.0。

## 发版步骤（下次照做，只在 `main` 上加目录）

```bash
cd agri-llm-demo && node build.mjs && node test/v03.mjs      # 构建 + 自检（须全绿）
git worktree add ../main-site main                          # Pages 走 main 根目录
mkdir -p ../main-site/vX.Y
cp index.html build-meta.json ../main-site/vX.Y/            # 只放产物（+ 指纹）
#  更新 ../main-site/versions/index.html 与 ../main-site/VERSIONS.md（新增一行）
cd ../main-site && git add -A && git commit -m "publish: vX.Y …" && git push origin main
git -C ../agri-llm-demo tag -a vX.Y.0 <源码提交> -m "AgriLink VX.Y · 构建指纹 <hash>"
git -C ../agri-llm-demo push origin vX.Y.0
# 局域网：cp index.html build-meta.json ../lan/vX.Y/ 并更新 ../lan/index.html
# 最后：实际访问两个地址核对 HTTP 200 / 指纹 / 功能（不动根 index.html）
```

## 历史说明（为什么以前有多个仓库）

V0.4—V0.7 期间每发一版建了一个独立仓库（`agri-llm-demo-v04` / `-v05` / `-v0.6` / `-v0.6.1` / `-v0.6.2` / `-v0.7`）。
2026-09-22 已把这些版本的产物**收进本仓库按目录发布**，并把这 6 个仓库**归档**（只读、地址仍可访问、描述指向新地址）。
彻底删除需要 GitHub 的 `delete_repo` 权限，本机 token 只有 `repo` scope，所以删除留待产品在网页端点删或给 token 加 scope 后执行。各版本的 `PUBLISH.md` 存档在 `docs/releases/`。

顺带发现并纠正的一处旧账：`agri-llm-demo-v05` 仓库后来被 V0.6 的产物覆盖过，该地址当时看到的其实不是 V0.5；现在 `/v0.5/` 用的是真正 V0.5 产物（`c44a4783ed88`）。

## 回滚

- 单版本回滚：直接把上一个版本的地址给出去（每个版本的目录都在）。
- 目录下线：删除对应 `vX.Y/` 目录 + 更新 `VERSIONS.md` 与 `versions/index.html`。
