# V2.8.3 · 无坐标事实进入右侧卡片区（需求 4.2.3）

## 缺陷（验收定位，已确认并复现）

事实层搜索「公开直播」**返回 0 张卡**，但按 id 直开能正常出画。根因三层，和验收给的定位一致：

1. 过滤器层正常：`F.facts({q:'公开直播'})` = 11 条；
2. 这 11 条直播事实 `lng/lat = null`（清单源没有坐标），共 14 条无坐标事实（全部 L1）；
3. `renderCards` 走 `F.factsAtLevel(st)`，而它用 `V03Scope.includes()` 做地理收窄，**无坐标事实永远为 false** → 卡片区为空。

**这不只是直播源的问题**：需求 4.2.3 明确右侧卡片区要承载「没有坐标、无法在地图上显示的事实」，当前口径与需求相悖。

## 修法

- `src/v03/filter.js` 新增 `factsForCards(s)`：有坐标的事实仍按地理范围收窄；**无坐标事实按 `geo.scopeLayer` 声明的层级归属视野**（L1 全局事实在任何视野的卡片区都出现），并按同一排序返回。
- `src/v03/fact.js` 的 `renderCards` 改用 `factsForCards`；**地图侧不变**（无坐标本来就不画点）。
- 概览数字（当前事实）仍用地理口径，避免改动已通过验收的 ②③ 相关口径。

## 验证

- `node test/v23-media.mjs`：**先走真实用户路径**——搜「公开直播」→ 断言右侧卡片区出 11 张卡（全部 `v23-live-*`）→ **逐张点击卡片**打开详情 → 在页面内出画。搜索出卡断言此前缺失，正是这个缺口让缺陷漏到了线上。
- 实测：11/11 卡在列（`dom=11 live=11 data=11`），播放 10–11/11（单路偶发受网络影响），解码器 ≤1、iframe 0。
- `npm run test:all`、`test:v27`、`v28-delivery`、`v26-delivery`、`v26-business` 全部通过；`test/v23-interactions.mjs` 的“点击流动点”改为轮询（12 秒内出现即可），此前单次采样偶发误判失败。
