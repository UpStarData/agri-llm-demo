# V10 · 数据概览大数字（v0.7）

> 触发：产品反馈「https://hyperresearch.ai/ 这个数字效果是我所需要的」（附该站 `301,162,991,918` 数字截图）。

## 参考对象到底是什么效果

扒了源站实现（`hyperresearch.ai` → `/assets/Reach.*.js` + `index.4oX0dObk.css`），它的数字效果是四件事，不是花哨动画：

| # | 源站做法 | 我们对应实现 |
| --- | --- | --- |
| 1 | **全位数 + 千分位**（`301,162,991,918`），不缩写 | 主数字改为 `125,000,009` 这种全位数（原来是「1.25 亿」） |
| 2 | **等宽数字** `font-variant-numeric:tabular-nums` + `font-feature-settings:"tnum" 1`，尾数翻滚时字位不跳 | 同款两条 CSS，加 `-webkit-` 前缀 |
| 3 | **数字一直在走**：值 = 基数 + 速率 × 已过秒数，`requestAnimationFrame` 逐帧重绘；弱动效环境降级为 1s 一跳 | 同款公式，速率 = 当日新增 / 86400、**最低 1 条/秒**（三级类型粒度下也看得见尾数在动）；`prefers-reduced-motion` 时 1s 一跳 |
| 4 | 字号大、字重中等、**负字距** `-.05em`、行高 1；下方一行小字标注口径 | 34px / 400 / `-.05em` / `line-height:1`；下方「事实条数」+ 口径小字（每个三级类型 100 万 条 · 本视野采样 20000 点） |

差一处：源站数字是整幅 hero（`clamp(2rem, 9.2vw, 8.5rem)`），我们的位置受**第二轮指令「统计指标只进左侧图层菜单、页面主体不显示」**约束，所以放在左菜单「数据概览」里，按菜单内宽取 34px（390px 窄屏 28px）。要改成地图上的巨型数字横幅，需要先解除那条约束。

## 实测

| 验证项 | 结果 |
| --- | --- |
| 自检 `npm test` | **69/69 通过**（含本轮新增 4 条：格式/字号/等宽、持续递增、**只增不减**、390px 不溢出） |
| 数字持续递增 | `125,000,008 → 125,000,023`（3s，≈5 条/秒） |
| 层级联动 | 全球 `125,000,0xx` / 中国 `12,500,0xx` / 湖南 `1,250,0xx` |
| 终端联动 | 流水每处理一条，主数字即时 +1，「实时接入 +N 条/今日」同步翻牌 |
| 字号与等宽 | 34px（390px 屏幕 28px）· `tabular-nums / "tnum"` · 数字宽 ≤ 菜单内宽 |
| 控制台 / 溢出 | 0 错误 · 1440×900 与 390px 均 0 横向溢出 |
| 截图 | `shots/v07-01-fact-default.png`、`v07-02-menu-number.png`、`v07-03-number-zoom-a/b.png`（隔 3s 两张，尾数在走）、`v07-04-menu-number-390.png` |

| 局域网实测 | `http://192.168.1.83:3101/v0.7/` 产物 HTTP 200、7,155,390 字节；页面实测 `125,000,008 → 125,000,022`（3s）、34px、`tabular-nums`、页面自身 0 错误 |

> 一个自己踩到并修掉的坑：菜单每次重绘都会重挂数字节点，重挂时若不去结算「已走时间」，一次终端事件重绘就会把数字往小里画（局域网实测出现过 `125,000,010 → 125,000,009`）。现改为把 elapsed 折算进基数（`ovTick`），并加了「只增不减」抽样回归。

## 已知限制

- 后台标签页里浏览器会暂停 `requestAnimationFrame`，数字随之停走（回到前台继续）——与源站行为一致，属预期。
- 数字是**展示口径**（体量模型 + 当日新增折算），不是真实落库行数；内部仍以 `dataMode` 区分真实/生成明细。
