# 3.11 直播接入：架构方案（不是页面改动）

## 结论先说

《直播怎么做.zip》里的系统是 **Node 后端 + Playwright 取流 + HLS 代理 + captureStream/WebRTC + 四川私密会话**。
现在的演示制品是 **GitHub Pages 上的单文件静态页**，浏览器端不可能完成"原页加载 → 发现 HLS → 代理分片 → 鉴权"这些动作。
所以 3.11 不是"改页面"能完成的，必须**把附件里的服务跑起来**，页面只做消费端。这是架构边界，我之前没有讲清楚。

## 方案 A（推荐）：静态页 + 同机常驻直播服务

```
浏览器（静态单文件，GitHub Pages）
   │  <video> / hls.js  —— 只请求同源或已授权的代理地址
   ▼
直播服务（Node 22，跑在演示机 192.168.1.83，端口 4173）
   ├─ resolver.mjs   Playwright 无头加载原页 → 抓真实 m3u8（校验 #EXTM3U）
   ├─ server.mjs     把 m3u8 里的子清单/分片/URI 重写到 /media/...
   ├─ cctv-relay.mjs CCTV-17：captureStream → WebRTC
   └─ work/private/  四川 storageState（600 权限、gitignore、永不出制品）
```

要点：

1. **服务侧**：直接沿用附件源码（`cd source/live-wall-web && npm ci && npm start`），`HOST=0.0.0.0`，局域网可访问；
2. **页面侧**：视频事实卡片的 `hlsUrl` 由构建期注入的 `LIVE_BASE`（如 `http://192.168.1.83:4173`）拼出代理地址；**制品里只有地址，没有任何 token/密钥**；
3. **交互**：沿用现有「视频自动播放」开关——开=挂载播放器并静音自动播；关=卸载播放器（省流量）；
4. **降级**：服务不可达时卡片自动回落到"静态卡片 + 外链"，不显示空白播放器；
5. **合规**：私密会话只存在服务机 `work/private/`，不进 Git、不进制品、不进日志；README 已列明。

代价与前置条件：

- 演示机需长期开机并有 Node 22 + Chromium（附件已说明）；
- 页面要访问该服务，需要 CORS 或反代（推荐把服务挂在 3100/3101 同域的 `/live/` 下，避免跨域 cookie 问题）；
- GitHub Pages 是 https，页面内嵌 http 服务会被浏览器拦截 → 要么服务也上 https（自签/内网证书），要么把整个演示也放到该机器的 http 下访问（`http://192.168.1.83:3101/v3.4/`）。

## 方案 B（降级，不部署服务）：只做"公开频道直链"

- 只挑**无需登录、直链可播**的频道（如部分公开 HLS），页面 `<video muted autoplay playsinline>` 直接播；
- 不涉及代理与鉴权，静态页即可，但覆盖面小、链接会失效，且无法覆盖 CABLE/私密源；
- 作为过渡可以立刻上，但要跟刘洋说清"这不是附件里的那套能力"。

## 我需要的决策

1. 选 A 还是 B（我建议 A；B 只能算过渡）；
2. 若选 A：演示机是否允许常驻这个 Node 服务、端口用哪个、页面是否改从 `http://192.168.1.83:3101/v3.x/` 访问（解决 https→http 混合内容）；
3. 40 路清单里哪些必须"身份核验后"才算接入（附件明确写了：能出画面 ≠ 已核验目标台）。
