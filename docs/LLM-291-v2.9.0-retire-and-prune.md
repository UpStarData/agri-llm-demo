# V2.9.0 · 首次加载后的定时退场 + 时间筛选的「动画内消失」

用户 2026-10-19 两点：

## ① 首次加载动画结束后，每 10s / 20s / 15s 退场一个点；新增继续；三个视角口径一致

- **节奏**：`RETIRE_CYCLE = [10000, 20000, 15000]` 循环，从「首屏铺点动画完成」那一刻开始计时
  （`feed.complete()` → `startRetire()`）。实测首屏之后 21 秒内自动退掉 1 个点。
- **退场单位是「坐标点」**：同坐标的多条记录在地图上本来就是一个点，退场时一起退出（实测退一个点可能少 1–2 条记录）。
- **跨视角一致**：退场登记在 `filter.js` 的共享集合 `retiredCoords`（按坐标），所以切到**中国 / 湖南**视角同样看不到；
  新增走原有亮星接入（真实入库），因此各视角都能看到新增（实测 55,223 → 55,224 条）。
- 一进一出：约每 10/20/15 秒掉 1 个点，亮星每 3/8/6/2/8/1 秒加 1 条，数据量整体保持。

## ② 时间筛选：消失发生在铺点过程中，动画结束即冻结

上一版是「动画结束后再退 1/20」，用户要求改为**动画过程中**：
先把点从无到有铺出来，过程中**随机**掉约 1/20，同时新点继续铺；**动画一结束就冻结**，不再新增或消失。

- 选点：`Fisher–Yates` 随机取 `n/20`（用户明确要"随机的"，所以每次点同一个筛选退的是一批新的点）；
- 每个退场点有独立淡出窗口：起点落在动画 **45%–82%**，淡出时长 **18%** 且被钳制到「不晚于动画结束」，
  因此动画最后一帧恰好把 1/20 收干净；
- 动画结束后不再重绘（`grow` 的 rAF 在 `p>=1` 那一帧画完即停）。

实测（30 天，逐 150ms 采样）：`0ms:399 → 450ms:1086 → 1050ms:1293（已有 9 个在淡出）→ 1500ms:1521 → 1800ms:1518 → 之后 1518 恒定`；
plan 口径 `selected 533 / pruned 27 = 5.1%`；两次点同一个筛选的可见坐标组 509 vs 507、交集 482（随机性成立）。

## 开发中发现并修掉的一个真 bug

`coordKeyOf` 最初写成 `f.lng.toFixed(4)...`，而事实层有 **11 条无坐标事实**（直播源 `lng=null`），
在共享过滤器里抛错导致整页初始化失败（ECharts 侧报 `queryComponents` undefined）。
已改为 null 安全（无坐标返回 `null`，不参与退场判定）。
