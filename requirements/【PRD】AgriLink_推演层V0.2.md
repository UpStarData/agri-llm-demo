# 一、需求背景

农业经营管理者在做采购、促销、调运、供应调整等决策前，需要评估方案可能产生的影响、风险和机会。事实层提供现实依据，关联层理清对象关系，推演层在隔离环境中模拟变化，生成带证据和不确定性说明的分析报告。

推演层围绕具体经营问题，基于事实层和关联层的现实数据，在独立的模拟环境中推演未来变化。每次推演绑定唯一 `run_id`，推演过程产生的对象、关系和事件不写回事实层或关联层。用户可从报告回溯推演过程、现实关系和原始事实，并围绕报告继续追问。

本版本（V0.2）面向 11 月 15 日展示，快速上线核心推演能力。推演层不显示地图，采用左右结构 + 底部终端的布局。

# 二、需求价值与目标

## 2.1 需求价值

| 价值点          | 说明                                                |
| ------------ | ------------------------------------------------- |
| 事前评估，降低决策风险  | 在实际执行经营动作前，模拟评估可能的影响和风险，避免盲目决策导致的损失。              |
| 基于现实数据的推演起点 | 推演从事实层和关联层的现实依据出发，不是凭空猜测；用户可核对推演使用的种子，判断推演前提是否可靠。 |
| 过程透明，结论可追溯  | 推演过程、模拟事件、观察指标变化全程记录；报告结论可回溯到推演轮次、现实关系和原始事实。      |

## 2.2 产品目标

| 目标        | 说明                                                                   |
| --------- | -------------------------------------------------------------------- |
| 推演与现实隔离   | 每次推演绑定唯一 `run_id`，推演产生的对象、关系和事件不写回事实层或关联层；现实数据不因推演而改变。           |
| 报告内容可区分   | 报告明确区分现实事实、推演假设、模拟事件、推演结果和系统建议；不将模拟结果伪装成现实预测。                    |
| 结论可追溯     | 报告中每项重要判断可回溯到推演轮次、现实关系或原始事实；无法追溯的内容明确标注"推演生成，无现实证据"。              |
| 数据缺口透明    | 报告说明推演使用的假设、缺失数据和不确定性，供用户判断结论是否适用于当前经营问题。                        |
| 追问限定在本次运行 | 深度追问和回答绑定当前 `run_id`，不与其他推演混用；超出本次推演范围的追问给出提示，不生成无依据的回答。          |

| 推演假设       | 推演层 | 用户输入的经营动作或系统推断的前提条件，与现实事实严格区分，在报告中标注为 [假设]。                                    |
| 历史数据周期     | 推演层 | 推演使用的历史数据周期。如选"最近 3 个月"，系统加载最近 3 个月的事实和关系作为推演依据。                            |

## 3.4 整体业务流程

推演层依赖事实层和关联层提供的现实依据，围绕用户的经营问题开展模拟推演，生成分析报告。

### 3.4.1 推演发起流程

1. 用户从事实层或关联层选择相关事实、本体或关系，进入推演层；系统自动带入选定内容作为种子。
2. 用户（可选）上传附件补充上下文，配置历史数据周期、推演轮次、环境模式、报告风格。
3. 用户在富信息输入框中用自然语言描述要分析的问题、经营动作或希望评估的变化。
4. 系统校验：至少有一类有效输入（保留的系统种子、成功解析的附件、推演要求，三者至少其一）。
5. 点击发送，系统生成唯一 `run_id`，创建推演任务记录，进入推演运行页。

### 3.4.2 推演运行流程

推演运行页按七个阶段依次执行（用户在同一页面看到阶段切换）：

1. **本体确认**：从关联层加载相关本体，形成本次推演的对象清单。
2. **GraphRAG 构建**：整理现实事实、本体、关系，形成推演上下文快照。
3. **生成 Agent 人设**：为参与推演的主体生成简化配置（类型、初始状态、行为规则模板）。
4. **生成模拟配置**：确定推演参数（品种数、种子数、时间指标、轮次、环境模式、Agent 数量）和用户输入的文本信息。
5. **初始方向启动**：设置开局条件，例如将政策调整作为触发事件，激活进口商和物流商，以当前库存及价格作为初始条件。
6. **双/单环境推演**：市场交易环境和产业协作环境并行运行（或单环境），按轮次模拟事件、更新状态、记录观察指标。
7. **报告生成**：按报告结构生成推演报告，完成后底部终端隐藏，进入报告查看状态。

### 3.4.3 推演报告查看流程

1. 报告生成完成后，左侧自动切换为报告主内容区，展示报告正文。
2. 用户阅读报告，了解推演背景、过程、结果、风险与机会、决策建议、数据缺口与局限。
3. 用户点击报告中的重点结论，跳转到对应的推演轮次、现实关系或原始事实（证据回溯）。
4. 用户在右侧 Agent 追问区输入问题，相关 Agent 对问题评论或回复（以群聊场景呈现）。
5. 用户可切换左侧主内容区查看推演知识图谱，了解本次推演涉及的本体和关系网络。
6. 用户可扫描二维码在手机查看报告，或导出 HTML 格式报告。

# 四、产品方案细节

## 4.1 推演层整体布局

**需求背景**：推演层不显示地图，采用左右结构 + 底部终端的布局。推演发起页、推演运行页、推演报告页共用相同骨架，通过左右内容区的切换实现阶段过渡。

**页面路径**：顶部三层 TAB「推演层」，默认进入推演发起页。

**页面结构**：

- **顶部**：AgriLink 三层导航（事实层 / 关联层 / 推演层），当前 TAB 高亮；
- **左侧区域**：推演发起页显示历史推演记录；推演运行页显示推演知识图谱；推演报告页显示报告主内容（支持切换为推演知识图谱）；
- **中间主输入区**（仅推演发起页）：富信息文本框，用于输入推演要求、展示系统种子、上传附件、配置项；
- **右侧区域**：推演发起页显示推荐内容；推演运行页显示阶段进程与 Agent 信息；推演报告页显示 Agent 列表与追问区；
- **底部终端**：推演运行页显示运行日志；报告生成后隐藏。

【📷 原型图：推演层整体布局】

| 页面     | 左侧区域   | 中间主输入区       | 右侧区域       | 底部终端      |
| ------ | ------ | ------------ | ---------- | --------- |
| 推演发起页  | 历史推演记录 | 富信息文本框（种子/附件/配置/推演要求） | 推荐内容       | —         |
| 推演运行页  | 推演知识图谱 | —            | 阶段进程/Agent 信息 | 运行日志终端    |
| 推演报告页  | 报告主内容  | —            | Agent 列表/追问区 | 隐藏        |

> 推演层三个页面在同一工作区内通过内容切换实现阶段过渡，不跳转 URL。

## 4.1.1 浏览器交互边界

**页面说明**：用户在浏览器中打开推演层页面，进入推演发起或推演运行时，需要处理以下边界情况。

| 功能点      | 页面交互 | 页面说明                                                                                                                                                     |
| -------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 后退提示     | —    | 用户点击浏览器后退按钮时，若推演任务正在运行，弹出提示："推演任务正在运行，后退不影响任务继续，是否确认后退？"<br>用户确认后退，页面返回上一页，推演任务继续在后台运行。                                                       |
| 刷新提示     | —    | 用户刷新页面（F5 或强制刷新）时，若推演任务正在运行，弹出提示："推演任务正在运行，刷新不影响任务继续，是否确认刷新？"<br>用户确认刷新，页面重新加载，推演任务继续在后台运行。                                                 |
| 关闭标签页提示  | —    | 用户关闭浏览器标签页时，若推演任务正在运行，弹出浏览器原生提示："推演任务正在运行，关闭页面不影响任务继续，是否确认关闭？"<br>用户确认关闭，页面关闭，推演任务继续在后台运行。                                                |
| 任务后台继续运行 | —    | 推演任务一旦发起（生成 `run_id` 并创建任务记录），后台持续运行，不受页面后退、刷新、关闭影响。<br>若任务因系统原因异常结束，系统自动标记任务状态为"失败"，用户可在历史记录中查看失败原因，并重新发起推演。                          |
| 重新进入运行页  | —    | 用户关闭或后退后，可通过历史推演记录点击"运行中"的任务，重新进入推演运行页，查看当前阶段进度和日志。<br>说明：重新进入时，页面从后端拉取当前任务状态、阶段进度、图谱数据和日志，展示最新状态。                                   |

## 4.2 推演发起页

**需求背景**：让用户知道本次推演带入了什么、能补充什么，并通过自然语言说明希望分析的问题，然后发起推演。

**页面路径**：顶部三层 TAB「推演层」，默认进入推演发起页。

**页面说明**：推演发起页采用三栏布局：左侧历史推演记录、中间富信息文本框、右侧推荐内容。中间富信息文本框是核心输入区，参考 ChatGPT 布局，支持文本输入和富信息粘贴（纯文本、图、图加文），复制图加文时不丢失图。

#### 4.2.1.4 发起推演校验与启动

**触发**：用户点击底部右侧【发送】按钮（或回车）。

**校验逻辑**：至少满足以下条件之一，否则按钮置灰，提示"请至少输入推演要求、保留系统种子或上传附件"。

1. 保留了系统种子（未点击【清空】，或点击【清空】后点击【恢复】）；
2. 上传了附件且解析成功（解析失败的附件不计入）；
3. 在中间输入区填写了推演要求（非空）。

**启动流程**：

1. 校验通过后，系统生成唯一 `run_id`（格式：`run_YYYYMMDD_NNN`，例如 `run_20261007_001`）；
2. 创建推演任务记录，写入数据库：
   - `run_id`：推演任务唯一标识；
   - `title`：推演标题，从推演要求中提取关键词生成，最多 30 字（如"长沙车厘子促销评估"）；后续报告生成后可优化标题；
   - `status`：推演状态，初始为"运行中"；
   - `created_at`：创建时间；
   - `config`：推演配置（历史数据周期、推演轮次、环境模式、报告风格）；
   - `seeds`：系统种子（事实 ID 列表、本体 ID 列表、关系 ID 列表）；
   - `attachments`：附件种子（附件 ID、文件名、解析后的文本）；
   - `user_input`：推演要求（用户在中间输入区填写的内容）。
3. 跳转到推演运行页，开始执行七阶段推演流程。

**说明**：点击【发送】即创建推演任务，推演任务创建后立即生成推演标题并写入数据库。推演标题从推演要求中提取关键词生成（如用户输入"评估长沙市场车厘子促销影响"，提取为"长沙车厘子促销评估"）。报告生成后，系统可根据报告内容优化标题，或用户手动修改标题。

### 4.2.3 右侧推荐内容

**页面说明**：右侧展示系统推荐的推演主题或与当前种子相关的推演建议。推荐内容分为两类：热门推演主题和相关推演建议。

**推荐内容生成规则**：

1. **热门推演主题**：从历史推演任务中统计近 7 天被发起最多的推演主题，取 Top 5。统计维度：推演标题的关键词（如"车厘子""促销""价格"）。生成方式：后端定时任务（每天凌晨 1 点）统计并更新热门推演主题列表。
2. **相关推演建议**：根据用户当前带入的系统种子，LLM 生成 3 条相关推演建议。生成逻辑：用户带入种子后，系统调用 LLM（Prompt："用户带入了以下种子：[种子摘要]，请生成 3 条相关的推演方向建议，每条不超过 20 字。"），LLM 返回 3 条建议。

| 功能点    | 页面交互 | 页面说明                                                                                                                                                        |
| ------ | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 热门推演主题 | —    | 展示近 7 天被发起最多的推演主题，最多 5 条。每条显示推演主题标题（如"榴莲价格波动推演""车厘子供应链中断推演"）。点击后，系统自动填充推荐的推演要求到中间输入区，用户可编辑后发送。说明：热门推演主题由后端定时任务统计生成，前端每次进入推演发起页时从后端拉取最新列表。 |
| 相关推演建议 | —    | 根据用户当前带入的系统种子，LLM 生成 3 条相关推演建议。每条显示建议标题（如"评估促销对价格的影响"）。点击后，系统自动填充推荐的推演要求到中间输入区，用户可编辑后发送。说明：相关推演建议在用户带入系统种子后实时生成，调用 LLM 生成建议。若 LLM 调用失败，显示"暂无推荐建议"。      |

**点击推荐项后的行为**：

1. 点击热门推演主题或相关推演建议后，系统自动将推荐的推演要求填充到中间输入区；
2. 用户可编辑推荐内容后发送；
3. 若推荐的推演要求与用户当前已填写的内容冲突，提示"是否覆盖当前内容？"，用户确认后填充。

## 4.3 推演运行页

**需求背景**：在同一页面中让用户看到系统正在处理什么、当前在哪个阶段、涉及哪些本体和关系、运行日志。推演运行页按七个阶段依次执行，用户看到阶段切换和进程变化，不等于七个单独页面。

**页面路径**：推演发起页 → 点击【发送】→ 自动跳转到推演运行页。

**页面说明**：推演运行页采用左右结构 + 底部终端的布局。左侧展示推演知识图谱，右侧展示阶段进程与 Agent 信息，底部展示运行日志终端。中间不显示富信息输入框，整个页面聚焦于推演运行状态的展示。

### 4.3.1 图谱更新规律总结

**页面说明**：推演知识图谱在七个阶段中的更新规律如下。

| 阶段序号 | 阶段名称        | 图谱更新规律                                           |
| ---- | ----------- | ------------------------------------------------ |
| 1    | 本体确认        | 图谱更新：从关联层加载本体，图谱中逐步显示本体节点（实线）。                 |
| 2    | GraphRAG 构建  | 图谱更新：从关联层加载关系，图谱中逐步显示关系连线（实线）。                 |
| 3    | 生成 Agent 人设 | 图谱不更新。本体节点上可能标注 Agent 配置状态，但图谱结构不变。         |
| 4    | 生成模拟配置      | 图谱不更新。                                           |
| 5    | 初始方向启动      | 图谱不更新。                                           |
| 6    | 双/单环境推演     | 图谱再次更新：推演过程中产生的新本体和新关系以虚线或不同颜色显示（橙色虚线）。      |
| 7    | 报告生成        | 图谱停止更新。用户可查看最终的推演知识图谱，包括现实本体/关系（实线）和推演新增（虚线）。 |

**图谱展示规则**：

| 功能点    | 页面交互 | 页面说明                                                                                                                   |
| ------ | ---- | ---------------------------------------------------------------------------------------------------------------------- |
| 图谱展示   | —    | 展示本次推演涉及的本体（节点）和关系（连线）。<br>本体节点按类型用不同颜色标注；关系连线按类型用不同颜色标注（颜色规则同关联层）。<br>支持放大缩小、手势操作。<br>支持不显示关系名称（只显示连线）。                   |

#### 4.4.2.2 报告 Markdown 风格说明

**Markdown 版本**：基于 GitHub Flavored Markdown（GFM）规范。

**格式要求**：

| 格式元素   | 说明                                                                                   |
| ------ | ------------------------------------------------------------------------------------ |
| 标题层级   | 使用 `#` 到 `######` 标记标题层级，最多支持六级标题。报告主体使用 `#` 作为报告标题，章节使用 `##`，子章节使用 `###`。                 |
| 段落与换行  | 段落之间空一行；段落内换行使用两个空格 + 换行符，或使用 `<br>`。                                                 |
| 列表     | 无序列表使用 `-`；有序列表使用 `1.`、`2.` 等。列表支持嵌套。                                                |
| 表格     | 使用 GFM 表格语法，支持左对齐、居中、右对齐。表格内换行使用 `<br>`。                                            |
| 代码块    | 行内代码使用 `` `code` ``；代码块使用 ``` 包裹，支持语法高亮（如 ```python）。                                |
| 引用     | 使用 `>` 标记引用块。                                                                        |
| 链接与图片  | 链接：`[文本](URL)`；图片：`![alt](URL)`。                                                    |
| 强调     | 加粗：`**text**`；斜体：`*text*`。                                                          |
| 证据引用标注 | 报告中有证据支撑的判断使用上标引用标记（如 `文本[1]`），点击后跳转到证据详情。<br>引用标记格式：`[1]`、`[2]` 等，对应附录中的证据条目。 |

**证据引用机制**：

报告中关键判断后添加上标引用标记（例如 `[1]`），标记可点击。点击后打开证据详情侧边栏或弹窗，展示证据类型（事实/关系/模拟事件）、证据内容、上下游证据链。

| 追问输入     | —    | 输入框供用户输入问题。支持多行输入，支持回车发送。                                                                                                                                      |
| 推荐追问问题   | —    | 系统根据报告内容自动生成 3-5 个推荐问题，展示在输入框上方（气泡样式）。点击推荐问题后自动填入输入框，用户可编辑后发送。推荐问题示例："为什么得到这个结论？""哪些事实支持这个结论？""哪个主体或事件影响了结果？""哪些结果不确定？"                                                                    |
| Agent 回复  | —    | 用户发送问题后，系统根据 Agent 的主体类型和推演过程中的参与度判断哪些 Agent 应该回复。相关 Agent 对问题评论或回复，回复以群聊消息形式展示（Agent 头像 + Agent 名称 + 回复内容）。回复内容区分依据类型（现实事实/推演结果），用标签标注。                                                  |
| 点赞认可 Agent 回复 | —    | 每条 Agent 回复右侧提供【点赞】按钮（或拇指图标）。用户点赞后，该 Agent 回复标记为"已认可"，并在下一次追问时作为核心上下文优先参考。说明：点赞机制让用户选择信任哪些 Agent 的回复，系统在后续追问时优先引用已认可的内容。                                                        |
| 追问限定在本次运行  | —    | 追问内容和回答绑定当前 `report_id` + `run_id`，切换到其他推演时，追问历史随之切换，不混用。超出本次推演范围的追问给出提示："此问题超出本次推演范围，建议创建新推演任务"。                                                                                          |

#### 4.4.3.3 追问示例

**用户追问**："为什么价格最终比促销前还高？"

**系统响应**（多个 Agent 回复）：

> **Agent：长沙某批发市场**  
> [模拟] 根据本次推演结果：
> 1. 促销导致初期需求激增（Day 1-7 交易量增加 35%），库存快速下降；
> 2. 智利产季已结束 [事实：`fact_2026_001`]，无法补充供应 [关系：`rel_001`]；
> 3. 替代产区（澳大利亚）到货价格为 52 元/斤，高于促销前水平；
> 4. 高价到货推高了市场均价。
>
> **注意**：此结论基于模拟推演，澳大利亚到货价格（52 元/斤）为系统依据行情推断，[不确定] 实际价格可能存在差异。

> **Agent：XX 进口商**  
> [模拟] 从我的角度补充：
> 1. 我在第 7 轮检测到库存告急信号，紧急联系了澳大利亚替代产区；
> 2. 澳大利亚产区当前处于产季早期，产量有限，报价较高（52 元/斤）；
> 3. 我权衡了运输成本和时效，选择了空运，进一步推高了到货成本。

用户点赞认可"长沙某批发市场" Agent 的回复，该回复标记为"已认可"。

**用户继续追问**："如果提前联系替代产区会怎样？"

**系统响应**（基于已认可的上下文）：

> **Agent：长沙某批发市场**  
> [模拟] 若提前联系替代产区（例如促销前 7 天），可能的变化：
> 1. 替代供应可在第 7 轮前到货，避免库存告急；
> 2. 提前采购可能争取到更好的价格（估计 48 元/斤，低于紧急采购的 52 元/斤）；
> 3. 市场均价可能控制在 42-44 元/斤，低于当前推演结果的 46 元/斤。
>
> **注意**：此为系统推断，建议创建新推演任务，调整"提前联系替代产区"假设后重新推演。

## 4.5 下次再做

以下功能本期（V0.2）不做，后续版本（V1.0+）再规划：

| 功能点              | 不做原因                          |
| ---------------- | ----------------------------- |
| 推演模板与快速配置        | V0.2 聚焦核心流程，模板化配置后续优化        |
| 推演对比（同一问题的不同假设对比） | 需要完整报告对比能力，V0.2 先支持查看单次推演    |
| 推演暂停/恢复/回滚       | 实现复杂度高，V0.2 失败后只能重新发起        |
| 推演并发运行           | V0.2 同一用户同时只能运行一个推演，避免资源冲突    |
| 完整 Agent Interview | V0.2 只支持围绕报告追问，不支持推演过程中对特定 Agent 的深度访谈 |
| 推演结果导出（PDF/Excel） | V0.2 只支持 HTML 导出             |
| 推演 API 接口        | V0.2 只提供 UI 操作，不对外暴露 API     |
| 数据报表风格           | V0.2 只支持专家风格（Markdown），数据报表风格（HTML 可交互页面）后期支持 |
